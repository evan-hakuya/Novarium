# AI 复核用 Workers AI 的判断模型，只由所有者手动触发

整理时可以借助 AI：用 `@cf/cloudflare/clairic` 从原稿开头识别书名、作者、简介，用 `@cf/cloudflare/clef` 判断候选行是章节、卷名、作者公告还是正文。规则仍是整理的主体，AI 只做辅助：没有配置、没有开启、额度用完或接口报错时，整理只用规则完成，不会失败。实测数据与接口见 `docs/agents/workers-ai.md`。

## 决定

- **只手动触发。** 整理预览不会自动调用 AI。元数据表单旁有「AI 识别元数据」，章节异常面板右上有「AI 复核章节」，两者各自独立。
- **默认关闭。** 后台设置页有 AI 总开关，存在 D1 的设置中；开启时提示「原稿片段会发送到 Cloudflare 处理」。Cloudflare 部署用 `ai` 绑定；Docker 部署用 REST 接口，账户 ID 与 API 令牌放在环境变量中，不进数据库。两者都没有配置时，界面不显示 AI 功能。
- **只在服务端调用。** 浏览器只请求 Novarium 自己的接口，令牌不下发到网页。
- **AI 识别元数据** 发送文件名和原稿开头约 3,000 字，只识别书名、作者、简介。结果作为建议显示在各字段旁，逐项「采用」或「全部采用」，不直接覆盖表单；返回 null 的字段不显示建议。标签、连载状态等由刮削提供（ADR 0006）。
- **AI 复核章节** 只发送候选行，不发送全文。每个候选行是一道 choice 题，题目包含本行、上一行和下一个非空行。调用前弹窗显示候选行数与预计占用的每日免费额度，确认后才开始。单次最多 640 行（10 批 × 64 题），由浏览器逐批请求服务端，显示进度，可取消；某一批失败时停止剩余批次，保留已完成的结果。第一版只用 `clef`，不做 clef-flash 与 clef 的两级方案。
- **默认只复核可疑行。** 实测中编号连续的「第 N 章」标题 AI 全部同意规则，发送它们只占额度。主按钮只发送可疑行：规则漏判的短行与没有编号的标题、涉及章节序号异常（乱序、重复编号、缺号前后两章）的标题、正文不到 500 字的章节标题、含「请假」「感言」等公告用词的行。次要按钮「复核全部」仍发送全部候选行。实教原稿从 779 行降到约 35 行。
- **结果按置信度处理。** 置信度不低于 0.8 的结果作为行级修正，直接修改划分，出现在「已修复」中并标记来源为 AI，可单条撤销或「撤销全部 AI 修正」。低于 0.8 的结果标为「待确认」放进异常面板，未处理时和乱序一样不能提交（缺号与重复编号自 #83 起只提示，见 GLOSSARY「章节异常」）。判为作者公告的行成为「作者公告」异常，默认操作是忽略。
- **行级修正叠加在规则结果上。** 一行用「去掉首尾空白后的文字 + 第几次出现」标识，不用行号：清洗选项改变时行号会变，文字通常不变。修正与忽略记在整理选项的 `lineOverrides`、`lineIgnores` 中，随版本保存，重新整理时继续生效。修改正则重新预览时，新出现的候选行没有结果，再点一次复核只发送这些行。撤销修复等于忽略，避免再次复核时被自动采用。
- **缓存在浏览器。** 整理预览在浏览器的 Web Worker 中完成，服务端没有整理草稿，所以 AI 结果缓存在 IndexedDB，键为原稿哈希、行标识、模型、提示词版本。整理保存成功后删除这份原稿的缓存；条目 7 天后过期，在下次打开整理页时清理。
- **失败重试。** Workers AI 偶尔返回 internal error：每批最多再试两次（1 秒、3 秒后），额度用完不重试。
- **第一版不显示用量。** Cloudflare 控制台可查每日 Neurons 用量。

## Considered Options

- 规则拿不准时自动调用 AI：省去一次点击，但费用不可控，原稿片段会在所有者不知情时发出。
- 常规 LLM 生成 JSON：要自己校验格式，也没有每题的置信度。clef 和 clairic 是强类型的判断与抽取模型，直接返回每个选项的概率，价格也更低。
- 发送全文让 AI 分章：一本书几万行，一次就会用完每日免费额度。
- 缓存存在 D1：要新增表与清理任务，而缓存只在浏览器中的预览阶段有用。
